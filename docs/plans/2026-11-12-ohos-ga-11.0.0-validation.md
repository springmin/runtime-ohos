### 1.1 本轮修正的 harness 问题

- `app_rect`：WMS 输出是 `[x y w h]`，旧代码按 `x1 y1 x2 y2` 使用，扫描区域在
  `x+w / y+h` 处提前结束，漏掉底部宽绿条，导致 `ADD_D/ADD_E` 角色缺失。已改为
  返回 `x y x+w y+h`。
- `ensure_app`：已运行 ability 的普通 `aa start` 在部分构建上是 no-op；改为带当前
  WMS rect 的重新激活，尽量把窗口置前。
- `slots_click_role`：每次点击前重新 `ensure_app`，避免动态槽创建后窗口被其他
  窗口盖住。
- `close_app_drawer`：MAUI flyout 是原生 overlay，a11y 树里没有文本；改为点击 app
  窗口右下空白区，既关闭 Drawer 又把 app 置前（无 Drawer 时是 no-op）。

## 2. AOT（GA patched host ILCompiler）

根因：GA SDK 的 stock `Microsoft.DotNet.ILCompiler/11.0.0` build integration 不含
OpenHarmony 补丁；runtime AOT pack 与 target ilc 本身没有缺件。修复 = 用
`runtime-ohos/src/coreclr/nativeaot/BuildIntegration` 的两个 targets 重打同版本 host
包，发布到 `aot-packs-11.0.0`（`Microsoft.DotNet.ILCompiler.11.0.0.nupkg`，

## 3. 默认签名

根因：宿主 `OPENSSL_CONF` 被 SDK 的 `hap-sign-tool` 继承，p12 解密报
`KEY_PASSWORD_ERROR`。`sign-hap.sh`（所有 pack 版本）与
`sign-for-device.sh`/`sign-huawei.sh`/`clipboard-acl-accept.sh` 已 unset
`OPENSSL_CONF/OPENSSL_MODULES/OPENSSL_ENGINES`；preview.34 默认 publish
`OpenHarmony: signed` 且 `publish_rc=0`。
