# FPS48：稳态 48fps 归因与 XComponent 期望帧率修复（FPS48，2026-10-05）

> 设备 HAD-W32（OpenHarmony-7.0.0.109 / API26 / 2in1），hdc 127.0.0.1:35111；件 = PERF-FINISH pfaot3 AOT（FPH 探针 WindowMs=600 + 测量壳，bundle `com.example.perf2`）+ 本机重建 host 两变体（源码仅差 `OH_NativeXComponent_SetExpectedFrameRateRange({60,60,60})` 一行；重建字节一致 `da61ed4c…`）；干扰件 = 另一个同款持续重绘 MAUI 应用（`com.example.hellomauiapp`，ActivityIndicator 每帧脏）。证据 scratch `fps48/`。

## 1. 二分（48 不是以下任何一项）

| 候选 | 判据 | 结论 |
|---|---|---|
| MAUI 动画定时器 / tick 间隔 | `OpenHarmonyTicker` 只是 16ms `System.Threading.Timer` 采样源，不产帧；帧由 XComponent onFrame 驱动（`OpenHarmonyAnimationLoop`+host `HasAnimations`），n≈callbacks、inc=0 | 非瓶颈 |
| 应用绘制成本 | FPH 单帧 draw 1.8–2.0ms、surf 0.5、a11y 0.1；60↔30 变化时 app work 不变，只有平台侧 `wait` 12.0→28.9ms、`pres` 变化 | 非瓶颈 |
| 显示刷新 / VsyncId | RS `activeMode=60` 全部 250+ 次采样；`fpsCount` 自启动累计 60/80/120、**无 48**（覆盖 PERF-FINISH 三次 10min） | 非面板模式 |
| 平台逐场景节拍 | onFrame 节奏由 RS 控帧分发：60 窗 wait_avg≈12.0ms、30 窗≈28.9ms（整 1/2 分频）；45–58 是 5s 窗内 60/30 混叠 | **是本因** |

- 无动画 = 0 app 帧：host 只在 `_dirty`（触摸/重绘请求/`HasAnimations`）时 Render，无 spinner 时只提交变化（INTERP-RENDER 门控），探针无输出；本轮 48/30 只出现在持续动画态。
- "慢速呼吸"假设排除：spinner 每回调 +24°（合理 60 需求）；48 期间应用侧无任何变化，纯平台节拍。

## 2. 对照实验（同件、同机、同样采样，只变一个条件）

| 条件 | 5s 窗 | 60 | ~30 | 42–55 过渡 | >60s 均值 |
|---|---|---|---|---|---|
| 清洁桌面（停第二重绘件）stock | 22 | 22 | 0 | 0 | 60.1 |
| 清洁桌面 vote60 | 20 | 20 | 0 | 0 | 60.1 |
| 第二件 t=60s 前台 stock | 26 | 9 | 8 | 9 | **46.2** |
| 第二件 t=60s 前台 vote60 | 36 | 36 | 0 | 0 | **60.0** |

- 空转 60s：清洁态 4min 无回落；干扰态在第二个持续重绘窗口出现后立即 60/30 交替（均值≈48，与 PERF-FINISH 记录的 48 主节奏一致）→ 48 是第二窗口出现后的平台帧仲裁，不是启动计时。
- 前后对照：stock 干扰态 46.2 → vote60 干扰态 60.0；单帧 `wait` 12.0/28.9ms、`pres` 2.5–4ms、`draw` 恒定。

## 3. 结论与修复

- 48fps = RS 控帧系统对**无投票** XComponent 的分频/仲裁（第二个持续重绘窗口出现时降到 30/48）；应用绘制、动画语义、显示模式均无辜；`VsyncId` 再次证实 ≠ App 呈现率。
- 修复（已实施）：host 注册 XComponent onFrame 时声明期望 60Hz；干扰态 46.2→60.0（前后对照见上）。
- 代价/后续：投票在注册期常驻（可见即 60）；按动画活动度动态撤票（idle 降档）列为后续项。
