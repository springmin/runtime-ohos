## 2. Naming convention (reviewer-mandated, jkotas)

All three PRs must use **`TargetsOhos`** (not `TargetsLinuxOhos`) — matching
`TargetsAndroid`/`TARGET_ANDROID` for Linux-based targets. Already applied across
the port (commit `602a5b135c8` + `955126211cc` + `bc53223bfb8` on the feature
branch); verify no stale `TargetsLinuxOhos` remains before each PR.

## 3. Non-OHOS platform impact

- **configuretools.cmake + apphost/static/CMakeLists.txt** are the only files that
  touch shared code paths; both are OHOS-guarded so non-OHOS behavior is
  byte-identical to upstream (verified by rebuild).
- **crossgen2 / `UseNativeAotForComponents`** (PR A): excluding OHOS from
  `UseNativeAotForComponents` means existing platforms keep their AOT publish
  (linux-x64/win-x64 unchanged); only OHOS switches to single-file IL.
- All other changes are either additive (`TargetsOhos` never set on existing
  builds) or keyed off `CLR_CMAKE_TARGET_OHOS` (never defined outside OHOS).
- **Full audit (2026-08-28):** all 36 port files reviewed line-by-line. The only
  cross-platform regression risk was the crossgen2 `PublishAot=false` /
  `NativeCompilationDuringPublish=false` attempt (breaks linux-x64/win-x64 AOT
  publish); it was replaced by the `UseNativeAotForComponents` exclusion
  (commit `01ba837d68c`). No other file affects non-OHOS behavior.

## 5. Order rationale (A → C → B)

1. **A first** — defines `TargetsOhos` + `TARGET_OHOS`; without it C's guards never
   fire and B's RIDs are un-consumable. Reviewers need A to understand C/B.
2. **C second** — A alone doesn't build OHOS (sysroot gaps: LTTng/gssapi/qsort_r);
   A+C together is the "it actually builds" story, reviewable as a pair.
3. **B last** — pure data (RID declarations); no dependency, non-blocking; the
   SDK-facing "productization" finishing move.

## 6. Branch/PR hygiene

- Create each branch from **latest upstream main** (`git fetch origin main`).
- Cherry-pick the file changes from `feature/ohos-cross-runtime` (or re-apply
  via `git checkout feature/ohos-cross-runtime -- <files>`).
- One commit per PR (grouped by concern), referencing tracking issue #132866.
- Draft PR first; ping area owners (build-system, coreclr, native-libs, sdk).
- Rebase onto main and re-run §4 validation before flipping ready-for-review.
