## BLOCKER: Console regression in the 26451.109 runtime

`dotnet new`, `dotnet build` (and likely most CLI verbs) crash with:

```
Unhandled exception. System.PlatformNotSupportedException:
System.Console is not supported on this platform.
   at System.Console.get_OutputEncoding()
   at Microsoft.DotNet.Cli.AutomaticEncodingRestorer..ctor()
   at Microsoft.DotNet.Cli.Program.Main(String[] args)
```

### Isolation (same machine, same muxer, console test app)

| shared framework | CoreLib size | Console.OutputEncoding / WriteLine |
|---|---|---|
| 11.0.0-rc.1.26451.1 (SDK-bundled) | 18.97MB R2R | **OK (enc=utf-8)** |
| 11.0.0-rc.1.26451.109 (SDK-bundled, PureIL) | 5.8MB | PlatformNotSupportedException |
| 11.0.0-rc.1.26451.109-r2r (R2R-PGO nupkg manual) | 18.97MB | PlatformNotSupportedException |
| 11.0.0-rc.1.26451.109-r2rpg (standalone R2R-PGO dir) | 18.97MB | PlatformNotSupportedException |

=> The Console support present in 26451.1 was LOST in the 26451.1 -> 26451.109
window (upstream merge). It is NOT a PureIL-vs-R2R difference (all 109
variants fail, all 26451.1 variants pass) and NOT a tty issue (26451.1 works
with stdout redirected).

### Impact

The 26451.109 SDK cannot build/publish on the OHOS device: the CLI host
(AutomaticEncodingRestorer) calls Console.get_OutputEncoding at startup and
dies before any verb runs. The earlier round-17c "full functional app"
verification had to use File.WriteAllText output because of this same
Console failure - at the time assumed to be an on-device Console limitation,
now proven to be this regression (26451.1 Console works fine on-device).

### Suspected cause (for build side)

Console support for OHOS must live in the runtime's ConsolePal platform
selection / terminal handling. The 26451.1 build carried it (probably an
OHOS-specific ConsolePal or a CoreLib/Console config); the upstream merge
into 26451.109 overwrote or dropped it. Check what made Console work in
26451.1 (compare System.Console.dll / ConsolePal selection / any
IsOpenHarmony gating) vs 26451.109. Note: Console works on the Linux build
machine, so this is OHOS-runtime-specific and did not block the build side.
