# MAUI-ohos P0 — in-app host probe (status 2026-09-16)

Goal (per the feasibility recommendation): the first acceptance point of the MAUI port is a
probe running **inside an OHOS app process** that proves (a) the graphics/window device nodes
are reachable from the app domain and (b) the ArkUI NDK can create/attach a UI node — the host
layer the future `Platform/OpenHarmony` slice builds on.

## Artifacts
- PoC project: `~/springsources/maui-ohos-p0/`
  - `entry/src/main/ets/entryability/EntryAbility.ets` — stage-model ability, creates a
    `NodeContent`, calls the NAPI probe, renders the attached native `Text`.
  - `entry/src/main/cpp/napi_init.cpp` — NAPI module: probes `/dev/dri/renderD128`,
    `/dev/dma_heap/system`, `/dev/vsync`, `/dev/mali0`, `/dev/binder` (+ binder version ioctl)
    and creates a `Text` via `ArkUI_NativeNodeAPI_1` attached with
    `OH_ArkUI_NodeContent_AddNode`.
  - `scripts/build-and-sign-manual.sh` — DevEco-less pack/sign chain (validated).
  - `RUNBOOK.md` / `README.md` — eligibility, steps, observed blockers.
- Evidence: `final-evidence/maui-ohos-p0-20260916.txt`.

## Verified on this device
- **Native module compiles** against the SDK 26 NDK (aarch64-linux-ohos, links
  `libace_napi.z.so`/`libace_ndk.z.so`/`libhilog_ndk.z.so`) — no device install needed.
- **Pack + sign chain works**: `ohos_packing_tool pack --mode hap …` produces a hap;
  `hap-sign-tool sign-profile` (debug alias `openharmony application profile debug`) +
  `sign-app` + `verify-app` → success (with the SDK's `OpenHarmony.p12`/`OpenHarmonyApplication.pem`;
  the shipped debug template is expired (2021→2024) and is regenerated with a fresh validity).

## Blocked on this device
- `hdc list targets` / `hdc shell` / `hdc install` → `Operation restricted by the organization`
  (MDM policy), so no app can be installed/launched here.
- The device is a commercial HarmonyOS device: the OpenHarmony debug profile is UDID-bound and
  the OpenHarmony debug CA may not be trusted for installation; an OpenHarmony device (or a
  HarmonyOS device with installation permitted + the right signing material) is required.
- No `hvigor`/DevEco on-device (the ArkTS compile step must run on a host with DevEco or with
  the SDK's ets-loader + `es2abc`; both `es2abc` and ets-loader exist in the SDK).
